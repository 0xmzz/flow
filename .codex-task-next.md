Add window/desktop computer-use primitives and a teach-me loop to Flow.
Read ARCHITECTURE.md, HUD_SPEC.md, commands.py, workflows.py, live.py first;
match existing style. The product goal: a LIGHT local brain that builds and
replays desktop workflows ("start the day" opens the usual apps placed on
the right monitors/desktops), and when it can't do something it ASKS the
user to teach it, then saves the result as a workflow.

## 1. Monitor + window placement (new module winctl.py)

- enumerate_monitors(): ctypes EnumDisplayMonitors -> ordered list of work
  areas [(index, left, top, right, bottom, primary: bool)]. No deps.
- place_window(title_query, monitor=None, region="full"): fuzzy-match an
  open window (reuse commands._windows_list/_match), restore if minimized,
  then MoveWindow to the target monitor's work area region. Regions:
  full, left, right, top, bottom, and quarters (top-left etc.).
- Speakable skill in commands.py: "put/move/place <name> on (the)
  (left/right half of) (monitor/screen) <1|2|one|two...>" and "<name> left
  half" style variants. Response like "Chrome on monitor 2, left half."
- Workflow primitive "place": {"do":"place","arg":"chrome","monitor":2,
  "region":"left"} using the same code path.

## 2. Virtual desktops

- Skill + primitive "desktop": "next desktop"/"previous desktop"/"desktop
  2" -> keyboard.send win+ctrl+right / win+ctrl+left (desktop N = press
  from a known edge is unreliable; implement next/previous only, and for
  "desktop N" respond honestly that Windows only exposes next/previous by
  key). Primitive {"do":"desktop","arg":"next"|"previous"}.

## 3. Teach-me loop (the core feature)

- In Router._fallback: when intent extraction yields action=answer BUT the
  utterance is imperative/action-shaped (starts with a verb-like token or
  the intent arg is empty and the text contains "open/put/set up/start/
  arrange" etc. — keep the heuristic simple and testable), do NOT just
  chat. Return a Question: "I don't know how to do that yet. Teach me the
  steps?" -> yes -> enter the existing creation_dialog, seeded with:
  name = a 2-4 word slug of the utterance, triggers = [the normalized
  original utterance]. -> no -> fall through to the normal chat answer.
- creation_dialog: accept the new place/desktop primitives as spoken steps
  ("put chrome on the left of monitor two", "next desktop", "wait two
  seconds", "open notion").
- After a taught workflow saves, confirm with: "Saved. Say '<trigger>' any
  time." The trigger phrase must be replayable immediately in the same
  conversation.
